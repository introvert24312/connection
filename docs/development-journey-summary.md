# WordTagger 项目开发历程总结

## 📖 项目概述

WordTagger 是一个基于 SwiftUI 的智能节点标签管理应用，从简单的数据管理工具演进为具备企业级架构的复杂系统。本文档总结了项目从概念到成熟产品的完整开发历程，重点记录技术挑战、解决方案和经验教训。

## 🎯 发展阶段回顾

### 第一阶段：MVP 构建 (2025年7-9月)
**目标**: 建立基础功能和架构框架

**核心成果**:
- 实现基本的节点和层管理
- 建立 MVVM + Service Layer 架构
- 基础的数据持久化和搜索功能
- SwiftUI 界面框架搭建

**面临挑战**:
- SwiftUI 响应式编程的学习曲线
- 数据持久化策略选择
- 用户界面设计的复杂性

### 第二阶段：多窗口架构实现 (2025年8月)
**目标**: 支持复杂的多窗口交互场景

**核心成果**:
- 实现独立窗口系统
- 建立 NotificationCenter 事件架构
- 窗口焦点管理基础框架
- 跨窗口数据同步机制

**技术突破**:
- 解决 SwiftUI 多窗口状态同步难题
- 建立了事件驱动的解耦架构
- 实现了窗口级别的状态隔离

**遇到的困难**:
- SwiftUI 窗口生命周期管理复杂性
- 多个Store实例间的数据一致性问题
- 事件传播时机的精确控制

### 第三阶段：稳定性危机与重构 (2025年8-9月)
**危机**: WebView 相关 API 废弃导致应用崩溃

**问题根源**:
- `allowUniversalAccessFromFileURLs` 在新版 macOS 中完全废弃
- `allowFileAccessFromFileURLs` 调用导致运行时崩溃
- 现有 WebView 安全策略不再适用

**解决方案**:
- 完全移除所有废弃的文件访问 API 调用
- 重新设计 WebView 安全策略
- 实现更安全的本地资源访问机制

**技术收获**:
- 深入理解了 WebView 安全模型演进
- 学会了向前兼容性设计原则
- 建立了 API 废弃监控机制

**经验教训**:
- 定期检查使用API的废弃状态至关重要
- 安全相关的API变更往往是破坏性的
- 需要建立回滚和应急响应机制

### 第四阶段：企业级可观测性构建 (2025年9月)
**目标**: 建立完整的分布式追踪和监控体系

**技术挑战**:
- 在 SwiftUI 响应式环境中实现 TraceContext 传播
- 设计轻量级但完整的追踪数据模型
- 实现跨服务的 Span 生命周期管理

**核心成果**:
- 构建了 TracingService 分布式追踪引擎
- 实现了 20 个服务的全链路追踪
- 建立了 TraceID (16字符) + SpanID (8字符) 标识体系
- 开发了 ObservabilityDashboard 实时监控界面

**创新解决方案**:
- **TracedServices 装饰器模式**: 无侵入式追踪集成
- **NotificationCenter 追踪传播**: 自动注入 TraceContext
- **异步Span收集**: 最小化性能影响
- **智能采样策略**: 平衡追踪覆盖度和性能

**技术收获**:
- 掌握了分布式追踪系统的设计原理
- 学会了在客户端应用中实现可观测性
- 理解了追踪数据的结构化设计

### 第五阶段：多窗口架构复杂性解决 (2025年9月)
**挑战升级**: 随着功能增加，多窗口协调变得极其复杂

**具体问题**:
1. **窗口创建竞态条件**: 层图谱窗口重复创建
2. **快捷键冲突**: Command+B 与系统书签冲突
3. **跨Store数据传递**: 对象引用在不同Store实例中失效
4. **通知路由混乱**: 同一通知被多个窗口重复处理

**解决方案详解**:

#### 1. 原子性窗口预留机制
```swift
// WindowFocusManager 中实现原子性检查
func reserveLayerGraphWindow(for mainWindowId: String) -> Bool {
    objc_sync_enter(self)
    defer { objc_sync_exit(self) }
    
    if layerGraphWindowReservations[mainWindowId] != nil {
        return false // 已预留，阻止重复创建
    }
    layerGraphWindowReservations[mainWindowId] = Date()
    return true
}
```

#### 2. 快捷键冲突解决
- **问题分析**: Command+B 与 Safari 书签快捷键冲突
- **解决方案**: 改为 Command+N (New Window 语义更清晰)
- **验证**: 确保新快捷键无系统级冲突

#### 3. 跨Store数据传递重构
```swift
// 修复前：传递对象（跨Store失效）
let userInfo = ["targetNode": node, "targetLayer": targetLayer]

// 修复后：传递ID，在目标Store查找
let userInfo = [
    "targetNodeId": node.id.uuidString,
    "targetLayerId": targetLayer.id.uuidString
]
```

#### 4. 智能通知路由
```swift
// 带源窗口验证的通知处理
.onReceive(NotificationCenter.default.publisher(for: .openMapWindow)) { notification in
    guard let userInfo = notification.object as? [String: Any],
          let sourceWindowId = userInfo["sourceWindowId"] as? String,
          sourceWindowId == self.windowId.uuidString else {
        return // 只处理属于自己的通知
    }
    // 执行窗口操作...
}
```

**技术收获**:
- 深入理解了多线程环境下的竞态条件
- 掌握了原子性操作在窗口管理中的应用
- 学会了复杂事件系统的调试和优化方法

## 💡 核心技术突破总结

### 1. 多窗口状态管理
**问题**: SwiftUI 多窗口环境下状态同步复杂
**解决**: 
- 事件驱动架构 + NotificationCenter
- 窗口级State隔离
- 原子性窗口操作

### 2. WebView 现代化
**问题**: 废弃API导致应用崩溃
**解决**:
- 完全移除废弃API调用
- 重新设计安全策略
- 建立API监控机制

### 3. 分布式追踪系统
**问题**: 复杂服务交互难以调试
**解决**:
- TraceID/SpanID 全链路标识
- 无侵入式追踪集成
- 实时可视化监控

### 4. 错误恢复机制
**问题**: 键盘事件处理错误导致状态混乱
**解决**:
- KeyboardEventManager 错误检测
- 自动状态清理和恢复
- 命令限流防止重复执行
